## What this is

Native SwiftUI iOS client (`ios/GoldManager`) for the "Gold Trading Manager". It talks to the **same Supabase backend** as the Next.js web app at the repo root — there is no separate iOS backend. Four feature modules, each surfaced as a tab and as Home Screen widgets:

- **Vàng** (portfolio) — gold holdings, market price, profit, buy/sell transactions
- **Quản lý thu chi** (budget) — monthly budgets per source: income, expenses, paid state
- **Tích góp** (savings) — savings wires with per-payment cells
- **iPad** — inventory, sales, profit, and debt tracking

## Build & run

```bash
cd ios/GoldManager
Scripts/sync-env-xcconfig.sh   # generate Config/Local.xcconfig from repo-root .env.local
xcodegen generate              # regenerate GoldManager.xcodeproj from project.yml
open GoldManager.xcodeproj
```

- Requires **iOS 17+**, **Swift 6** (strict concurrency complete), Xcode 27. Some widget features target iOS 27 and need Xcode-beta to build (see auto-memory).
- `project.pbxproj` is **generated by xcodegen** — never hand-edit it. Change `project.yml`, then re-run `xcodegen generate`.
- `Scripts/sync-env-xcconfig.sh` also runs automatically as a pre-build script. It reads the repo-root `.env.local`, accepting either `EXPO_PUBLIC_SUPABASE_URL`/`EXPO_PUBLIC_SUPABASE_ANON_KEY` or the web aliases `NEXT_PUBLIC_SUPABASE_*`, and writes the un-committed `Config/Local.xcconfig`.

## Verification (no XCTest target exists)

The scheme has no test targets. Verify changes with the commands from `README.md`:

- **Strict typecheck** — `xcrun swiftc -typecheck -parse-as-library -swift-version 6 -strict-concurrency=complete ... Sources/*.swift` (full command in README).
- **Live read-only smoke check** — compiles `Tools/SmokeCheck.swift` against the model/service files and runs it against real Supabase (sources `../../.env.local` first). `Tools/` is *not* part of any app target; it only exists for this check.

## Architecture

### Stores & views (one per feature)
Each feature is an `@MainActor @Observable` store (`*Store.swift`) plus its view(s) (`*View.swift` / `*Views.swift`, plus shared `EditorViews.swift`). `GoldManagerApp.swift` instantiates the four stores and injects them with `.environment(...)`; views read them via `@Environment`. The tab bar lives in `AppView`; deep links `goldmanager://tab/<portfolio|budget|savings|ipad>` (and the `GOLD_MANAGER_START_TAB` env var) select a tab.

### Networking — single actor over Supabase PostgREST
`actor SupabaseClient` (`Services.swift`) is the only network layer. It hits Supabase REST at `/rest/v1/<table>` with the anon key in `apikey` + `Authorization: Bearer`. Core gold/app-settings calls live in `Services.swift`; budget/savings/iPad calls are an **extension** in `FeatureAPI.swift`, built on the generic `restGet/restPost/restPatch/restDelete` helpers. There is no Supabase SDK — requests are hand-built `URLRequest`s; the Supabase anon role must allow select/insert/update/delete on the relevant tables.

After any **mutating** request (POST/PATCH/PUT/DELETE), `reloadWidgetsIfMutating` calls `WidgetCenter.reloadAllTimelines()` so widgets refresh immediately rather than on the ~30-min background cadence. Plain `load()` (GET) does not trigger a reload.

### Configuration injection
Supabase URL/key are injected at build time as Info.plist keys (`EXPO_PUBLIC_SUPABASE_URL` / `_ANON_KEY`, fed from `Config/*.xcconfig`). Stores read them via `Bundle.main.object(forInfoDictionaryKey:)`, falling back to `ProcessInfo` env vars (used by the smoke tool and run schemes). A value still equal to `$(...)` is treated as unset → `APIError.notConfigured`.

### Models & data conventions
Models (`Models.swift`, `BudgetModels.swift`, `IpadModels.swift`, `RoomModels.swift`, `PersonalModels.swift`) map snake_case DB columns via `CodingKeys`. **Newly added columns are decoded defensively** (`try?` + a default) so the app keeps working against a DB where the migration hasn't run yet — e.g. gold `owner`/`is_sold` (migration `supabase/migrations/20260627000000_add_gold_owner_and_sold.sql`). Dates go through `DateFormatters`: a 10-char string is a DB day `yyyy-MM-dd` (UTC), anything else an ISO-8601 timestamp; the JSON decoder branches on length.

### Widgets (`Widgets/`, separate app-extension target)
The widget extension does **not** use an App Group. Each widget **fetches directly from Supabase** through the same `SupabaseClient`, which is why `project.yml` compiles the shared files (`Services`, `FeatureAPI`, and the `*Models`) into **both** targets. `WidgetDataLoader.swift` builds per-screen snapshots + the AppIntents (configurable widgets like savings-by-wire, and interactive ones like the budget paid toggle, which write back through `SupabaseClient`); `GoldManagerWidgets.swift` holds the widget bundle and SwiftUI views.

> Note: `README.md` still describes an older App-Group snapshot mechanism — the code above is the current reality. Prefer the code.

### BTMC gold price (auto daily fill)
`BTMCGoldPriceClient` (`Services.swift`) reads BTMC's public price table (dynamic suffixed JSON keys, parsed in `GoldQuote.init(btmcRow:)`). On portfolio load, `PortfolioStore.autoFillIfNeeded()` writes the selected quote's price into `app_settings.current_gold_price` **once per day** (guarded by `gold_price_auto_date`). The `btmc.vn` HTTP exception is declared in `project.yml`'s `NSAppTransportSecurity`.

## Conventions specific to this repo

- **Adding a source file:** add it under `Sources` in `project.yml`; if a widget needs it, also list it under the `GoldManagerWidgets` target's `sources`, then `xcodegen generate`.
- **Comments and user-facing strings are Vietnamese.** Match the surrounding style.
- Formatting helpers live in `Theme.swift`: `Double.vnd`, `Double.goldWeight`, the `.vndInput` style, and `DeferredNumberField` for currency/decimal entry.
- App is forced to Light mode (`UIUserInterfaceStyle: Light` in `project.yml`).
- `DEVELOPMENT_TEAM` is set in `project.yml`. Free-account signing has constraints (no App Groups) — see the auto-memory note before changing capabilities.
